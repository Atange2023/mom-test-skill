# 三类坏数据的识别与化解（Deflect · Anchor · Dig）

## R — 原文 (Reading)

> "There are three types of bad data: 1. Compliments 2. Fluff (generics, hypotheticals, and the future) 3. Ideas"
>
> — Rob Fitzpatrick, Chapter 2, Avoiding bad data

> "once we start to notice, it’s easy to get back on track by deflecting compliments, anchoring fluff, and digging beneath ideas."
>
> — Rob Fitzpatrick, Chapter 2

**中译**：坏数据有三类——好评、泛泛之谈（泛化/假设/未来）、点子。一旦开始留意，就能用"挡开好评、把泛泛拉回具体、下挖点子背后的动机"重新回到正轨。

---

## I — 方法论骨架 (Interpretation)

即使你努力遵守三条铁律，对话仍会跑偏——你会兴奋地开始推销，或者为了解释为什么见面而不得不谈点子，或者对话卡在"想象的世界"里。关键不是"永远不犯错"，而是**认出三种坏数据，并用对应动作把对话拉回来**。

三类坏数据与三种化解动作一一对应：

| 坏数据 | 长什么样 | 化解动作 |
|---|---|---|
| **好评（Compliment）** | "太酷了""我喜欢""继续保持联系" | **挡开（Deflect）**：无视称赞，回到事实——"你们现在是怎么处理这件事的？" |
| **泛泛之谈（Fluff）** | "我通常""我总是""我会""我可能""你会不会……" | **拉回具体（Anchor）**：把话题从想象拽回已发生的事——"上一次是什么时候？带我过一遍。" |
| **点子（Idea）** | "你们能不能加个 X 功能""这个杀手功能很棒" | **下挖（Dig）**：追问动机——"这个功能能让你做什么？""没有它你现在怎么应付？" |

三者的共同本质：**它们都不需要对方付出任何代价**，所以真假难辨、信息量为零甚至为负（好评会制造假阳性）。这份清单的意义在于给你一个**在对话中实时自检的仪表盘**——一旦听到这三类信号，就执行对应动作。

一个关键心态：**你不需要"聊得愉快"才算成功**。一场揭示"他们其实不在乎"的负面对话，和一场揭示"他们很痛"的正面对话，价值一样高。不要在被好评安抚后停下来，也不要因为冷反应而强行"提升话术"直到对方改口——那只会收获假阳性。

## A1 — 应用示例 (Application Example)

### 示例 1：挡开好评（书中示例，章节 2）

- **问题/输入**：创始人滑进了推销，对方回应"That's really cool. I love it."
- **方法论的使用**：不把好评当数据。创始人道歉并挡开："抱歉我滑进推销模式了……你们现在是怎么处理这件事的？"
- **结论**：对方说出了真实做法——**两个全职员工**在维护流程，用 Excel 和大量邮件同步。
- **结果**：创始人由此发现"这件事居然值得两个全职人力"，是一条高价值信号；而结尾对方又补了一句好评（"我肯定它会做得很好"），再次被识别为无价值噪声。

### 示例 2：拉回泛泛之谈（书中示例，章节 2）

- **问题/输入**：对方声称"I'm an 'Inbox 0' zealot. It's totally changed my life."
- **方法论的使用**：不评价这句话，直接拉回具体："你现在收件箱里有多少封？""上一次彻底失控是什么时候？"
- **结论**：对方承认三周前旅行断网，**花了 10 天才恢复**。
- **结果**：泛泛之谈"我总是控制得很好"被补上了关键限定——"除了失控的时候，那是噩梦"。作者点明：用泛化词时，人描述的是**他想成为的样子**，而非真实的样子。

### 示例 3：下挖点子（作者亲历，章节 2）

- **问题/输入**：MTV 提出"需要分析和报表"。
- **方法论的使用**：最初作者照单全收，做了炫目的自助分析仪表盘——90% 是无用功，客户仍每周打电话要 CSV 邮件。后来终于下挖："你要这个功能做什么？"（让报表带上客户的 logo）
- **结论**：对方答："没几个人真看这些报表。我们的客户就是喜欢每周收到点东西，带点花样他们会更高兴。"
- **结果**：真相是"让客户开心"而非"更好地理解数据"。如果早点下挖，本可以做一件简单得多的事（每周定时发少量高层数字即可），省下三个月。

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?

1. 一场访谈/演示结束后，满耳都是夸奖，却拿不准到底学到了什么。
2. 对方抛出了一堆功能建议，不知道哪些该做。
3. 对话里出现了"我通常""我会""我肯定会用"这类词，感觉不对劲。
4. 已经意识到被带偏（自己在推销、或对方在敷衍），想在当场把话拉回来。

### 语言信号 (用户的话里出现这些就应激活)

- "所有人都说这个想法很好，但我心里没底"
- "客户提了一堆需求，我该做哪个"
- "他说明天就下单/他肯定会买"
- "对方一直在夸我，是不是没戏了"
- "compliments / fluff / feature requests / 好评 / 泛泛而谈"

### 与相邻 skill 的区分

- 与 `mom-test-three-rules` 的区别：那条是**事前不制造**坏数据；这条是**事中识别并修复**已经出现的坏数据。
- 与 `commitment-advancement` 的区别：这条处理"好评/泛泛"这类零代价信号；那条用"索取承诺"来处理有了一定产品后的真假验证。

## E — 可执行步骤 (Execution)

**必需输入**：① 一段对话记录/转录/回忆（原文最好）；② 本轮想学到什么（可空）。
**缺失处理**：若没有对话记录，先让用户把"听到的关键句"复述出来；无任何素材则改用"预演自检清单"。
**交付物与完成标准**：输出一张**坏数据清单**（分类 + 原句 + 判定 + 修复动作），并给出**修复后的对话脚本**。完成标准：每条坏数据都映射到一个具体动作。

1. **逐句过筛，标注三类坏数据**
   - 好评：无代价的称赞/鼓励（"很棒""加油""回头联系"）。
   - 泛泛之谈：含"通常/总是/从不/会/可能/要是……就……"。
   - 点子：功能请求、建议、"你们应该……"。
   - 完成标准：每条关键句都有分类标签。

2. **对每类执行对应动作**
   - 好评 → 挡开：一句感谢 + 立刻问事实（"那你们现在怎么做？"）。
   - 泛泛 → 拉回："上一次发生是什么时候？""带我过一遍当时的经过。"
   - 点子 → 下挖："这能让你做什么？""没有它你现在怎么应付？""这算必须的购买标准，还是锦上添花？"
   - 完成标准：为每条坏数据给出可照读的修复句。

3. **特别处理强情绪信号**
   - 愤怒 / 尴尬 / 过度兴奋都要下挖（"这似乎真的很烦你，一定有个故事"）。完成标准：为每个情绪点写一条下挖追问。

4. **判断能否原地挽回**
   - 若对话已无法挽回，至少把"这次学到的是坏数据"记下来，避免团队把它当成正面信号。
   - 判停条件：若已经拿到足够的**事实或承诺**，可以体面收尾，按 `finding-conversations` 要转介绍。

## B — 边界 (Boundary) ★

### 不要在以下情况使用此 skill

- 你正处在正常的**销售/成交**环节，需要客户给出正面反馈来推进——此时该用 `commitment-advancement`，而不是把一切正面话都当噪声。

### 作者在书中警告的失败模式

- 钓鱼式求表扬与 Ego 问题（The Pathos Problem）：一旦暴露 ego，对方就会开始保护你。
- 把"对方说会买"当成预订单；第一个创业公司因此损失约 1000 万美元。
- 照单全收功能请求 → 功能蔓延（feature creep）。
- 忽视强情绪信号（"一天中最糟的部分"被记一笔就跳过）。

### 作者的盲点 / 时代局限

- 作者建议"尽量避免提到点子"，但在需要透明沟通、需要对方一起定义的场景里，完全不谈点子并不现实。
- 例子主要来自 B2B 与线下，对纯线上消费者产品，"好评"与"真实兴趣"的区分更难。

### 容易混淆的邻近方法论

- 与"积极倾听"类通用技巧不同：本卡不是让你更会共情，而是**有意识地把零代价信息降权、把有代价信息升权**。
